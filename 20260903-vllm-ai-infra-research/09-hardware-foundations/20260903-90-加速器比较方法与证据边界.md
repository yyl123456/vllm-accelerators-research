# 加速器比较方法与证据边界

## 文档契约

- **唯一问题**：怎样在不混淆峰值、microbenchmark与serving evidence的前提下比较推理加速器。
- **In scope**：指标定义、证据层级、归一化、UNKNOWN、实验矩阵。
- **Out of scope**：具体计算/内存/互联机制（91-95）、vendor结论。
- **证据基线**：官方datasheet/docs、固定软件源码、设备实测三类独立来源。

比较单位不是“芯片名字”，而是完整system tuple：SKU/revision、card/node数量、memory容量/类型、power/clock、host/NIC/topology、firmware/driver/runtime/compiler/framework/plugin、model/quant/parallel/config。任一变化都可能改变结果。

证据分层：hardware design/datasheet说明理论资源；source说明存在路径；host/import说明软件可装载；device smoke说明路径能运行；numeric/eval说明语义；performance/SLO说明收益；failure/soak说明生产性。低层不能替代高层。

峰值TOPS/FLOPS需注明dtype、sparsity、矩阵形状和boost；memory bandwidth需区分pin/theoretical与sustained；interconnect需区分单link aggregate和collective effective。成本比较还需utilization、功耗、主机与网络、工程维护。

模型归一化保持weights/quant/quality、prompt-output分布与SLO一致。某backend缺feature时不能关闭后继续称等价。无硬件时输出公式、capability和实验计划，把系数标UNKNOWN；不得用厂商峰值估算E2E tokens/s后当结论。

最终表应同时列：可表示性、容量、prefill、decode、KV、MoE/communication、动态性、启动/artifact、可靠性、生态/版本负担。每格带证据等级和revision日期。

## 比较向量

| 维度 | 必须记录 | 常见误判 |
|---|---|---|
| compute | 单元/dtype/shape利用 | 峰值TOPS=吞吐 |
| memory | 层级/访问/reserve | 总内存=KV可用 |
| interconnect | topology/message/p99 | link peak=扩展效率 |
| runtime | queue/event/error/cancel | API return=device done |
| compiler | op/shape/artifact/fallback | 可编译=正确 |
| serving | SLO goodput/quality/failure | tokens/s=生产价值 |

证据按 datasheet→source→host→device→numeric→stress→performance→release 提升。`RECOMMENDATION`：选型表展示证据等级/UNKNOWN，禁止无 provenance 总分。
