# KV 量化、Offload 与容量推导

## 文档契约

- **唯一问题**：如何建立可审计的 KV bytes/capacity 模型，并评价量化和层级存储的交换。
- **In scope**：bytes 公式、profiling headroom、KV quant metadata、CPU/remote offload 成本。
- **Out of scope**：量化模型质量总论（15）、remote P/D protocol（36）、vendor memory hierarchy（91-95）。
- **证据基线**：vLLM `bb363db9...` 的 `kv_cache_interface.py`、`core/kv_cache_utils.py`、worker memory profiling 和 offloading connectors。

## 1. 基础容量公式

标准 decoder attention 在未考虑 padding/分片时，每 token KV bytes 近似：

`M_token = L * 2 * H_kv * D_head * bytes(dtype)`

context residency 为 `sum_requests(tokens_resident) * M_token`。但 vLLM 实际分配单位是 page，必须加入 group layer count、block size、layout padding、quant scales/zero points、alignment、replication/sharding、lookahead、graph workspace 和 allocator reserve。

可服务 token blocks 不是 `device_total/page_bytes`。应从可用 memory 扣除 weights、runtime、kernels/workspace、activation peak、communication buffers、graph captures、fragmentation/headroom，再除以统一 physical page bytes。

## 2. memory profiling 是协议

`determine_available_memory` 的输出必须说明测量阶段、峰值 workload、是否 graph capture、并发/sequence shape、runtime allocator 行为和 safety margin。第三方 worker 返回一个数字并不证明它与 CUDA profiling 语义等价。

多 rank 下容量由最紧约束 rank 与 parallel layout 决定。模型 weights shard 不均、MoE expert placement、driver reserved memory 都会造成异质 headroom。应保存 per-rank 原始值，而非只留最终 `num_blocks`。

## 3. KV quantization 合同

固定 revision 的 `KVQuantMode` 区分 per-tensor FP8、per-token-head INT8/FP8/INT4、NVFP4、TurboQuant 等模式。每种模式不仅改变 data bytes，还规定：

- scale/zero-point 粒度与存放位置；
- K/V 是否采用不同 bit width；
- packing、rotation 或 block scale；
- kernel 读写和 dequant 路径；
- page size 与 layout 是否变为 opaque bytes；
- transfer/serialization 是否保持 metadata。

若 capacity 只按 bit width 缩放而遗漏 scales、padding 和 minimum allocation，会高估收益。质量也不能只看 perplexity：长 context、attention sink、不同 head 与生成分布可能更敏感。

## 4. offload 的时间模型

将冷 KV 放到 host/SSD/remote tier 节省 HBM，但恢复延迟近似：

`T_restore = T_lookup + bytes/BW_effective + T_protocol + T_queue + T_unpack`

其中 effective bandwidth 受 NUMA、PCIe/IOMMU、pinned memory、DMA concurrency 与 compute contention 影响。若 restore 不在所需 token 前完成，TTFT/ITL 会出现长尾；若预取过早，又占回 HBM 并污染热 cache。

offload 的 correctness contract 是 versioned state：model/adapter/dtype/layout/group mapping 必须匹配；partial transfer 不能标 ready；请求取消后 in-flight DMA 要么安全完成到隔离 buffer，要么可取消，不能写入已复用 blocks。

## 5. 三种策略不可混称

- **quantization**：缩小每个 resident state，增加数值和 kernel 风险；
- **local offload**：改变 memory tier，增加搬运与 NUMA/PCIe 风险；
- **remote cache/P-D**：跨进程/节点改变 ownership，增加协议、租约和网络风险。

三者可叠加，但 evidence tuple 必须包含顺序与格式。例如“FP8 KV 可 NIXL transfer”需要证明 sender/receiver layout、scales 和版本相容，不可从两项功能分别可用推出组合可用。

## 6. 架构决策表

| 决策 | 主要收益 | 首要风险 | 必测指标 |
|---|---|---|---|
| 更小 block | 降低尾部浪费 | metadata/kernel 开销 | waste、lookup、tokens/s |
| 低 bit KV | 提高 capacity/BW | quality、dequant | 长上下文质量、ITL |
| host offload | 扩展可用 context | PCIe/NUMA tail | hit、restore p99 |
| 更高 reserve | 降低 OOM/preempt | 牺牲并发 | goodput、OOM rate |
| aggressive eviction | 给活跃请求让路 | prefix 重算 | saved vs recompute cost |

## 7. 无硬件时可确定与不可确定

静态可确定：公式、page descriptors、quant metadata 类型、配置约束、transfer API。需要设备：真实 allocator headroom、DMA overlap、kernel throughput、质量和长尾。文档必须保留符号参数和测量方法，不能填入伪精确带宽系数。

## 8. 输出清单

容量评审至少交付：per-layer/group state 表、per-rank fixed/variable memory、block/page bytes、最大/典型并发情景、reserve 来源、quant metadata overhead、offload bandwidth/latency budget、OOM/preemption fault injection 与 UNKNOWN 项。

## 9. 全文档统一变量表

本表是 30、32、34、36 与 vendor 容量章节的唯一符号 owner；其他文档引用而不重新定义。

| 符号 | 单位 | 定义 |
|---|---:|---|
| `L_g` | layer/group | KV group `g` 覆盖的 layers 数 |
| `B` | token/block | 逻辑 KV block 的 token 数 |
| `N_b` | block/rank | 某 rank 可分配 physical blocks |
| `H_kv,g` | head/layer | group 的 KV heads 数；已说明是 global 或 shard-local |
| `D_h` | element/head | head dimension |
| `b_K,b_V` | byte/element | K/V data 的有效存储 bytes；低 bit packing 用有理数或总 packed bytes |
| `M_meta,g` | byte/block | scale、zero point、page descriptor、alignment 等 metadata |
| `M_page,g` | byte/block | `L_g × B × H_kv,g × D_h × (b_K+b_V) + M_meta,g`，再按 layout 对齐 |
| `M_fixed,r` | byte/rank | weights、runtime、graph/trace、communicator 等固定驻留 |
| `M_peak,r` | byte/rank | profile shape 的 activation/workspace 峰值 |
| `M_reserve,r` | byte/rank | allocator fragmentation、driver 与 safety headroom |
| `M_KV,r` | byte/rank | 可分配给全部 KV groups 的预算 |
| `W_tail` | token | page rounding 造成的尾部浪费 |
| `R_rep/R_shard` | ratio | replication 与 sharding 对 per-rank bytes 的因子 |
| `M_wire` | byte/transfer | remote/offload 传输的 data+metadata+protocol 总 bytes |
| `T_restore` | second | tier/remote KV 恢复关键路径时间 |

容量守恒写作 `M_KV,r <= M_total,r - M_fixed,r - M_peak,r - M_reserve,r`；多 group 时为 `Σ_g N_b,g × M_page,g <= M_KV,r`。如果 backend 使用统一 page pool，还必须满足各 group 的 allocator sharing/alignment 规则，不能分别取整后超卖。

## 10. 证据分类

- `SOURCE_IMPLEMENTED`：固定 revision 的 KV spec、quant mode、page descriptors 与 worker memory API。
- `INFERENCE`：公式是审计模型；实际 backend 可采用 opaque layout，但必须给等价 measured page bytes。
- `RECOMMENDATION`：capacity artifact 保存每个符号的实值、单位、来源与 rank/group scope。
- `UNKNOWN`：无设备时的 `M_peak`、fragmentation、DMA overlap 与质量/性能收益。
