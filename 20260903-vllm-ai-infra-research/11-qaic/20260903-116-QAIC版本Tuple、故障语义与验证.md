# QAIC 版本 Tuple、故障语义与验证

## 文档契约

- **唯一问题/Owner**：QAIC backend如何形成可复现支持声明，并在device/QPC/runtime故障时收敛。
- **依赖输入**：74/86 release方法；110-115；84 failure owner。
- **唯一输出**：QAIC tuple、failure matrix、分层验收。
- **Out of scope**：重复mode机制。
- **源码基线**：vllm-qaic `3212cc...`，开发依赖指向vLLM v0.23.0；当前SDK网页只作外部最新参考。

tuple包含card/SKU/ISA、QID↔SBDF/topology、firmware/driver/Platform+Apps SDK、Torch QAIC/QEfficient、QPC compiler/schema、vLLM/plugin SHA、mode、model/quant/profile、device partitions/channels、features。

故障分PCI/MHI枚举、SoC非Ready、SDK/ABI、QPC load/activate、profile miss、submit timeout、device async error、output mismatch、P2P/communicator与host memory exhaustion。官方FAQ提供timeout和SoC reset方向，但生产不可把增大timeout当根因修复。

device reset后active handles/QPC/KV不可原地信任；replica应fail-stop并重建。request retry需考虑streamed tokens/RNG；late device completion必须以epoch隔离。

验收阶梯：source/import→`qaic-util`/runner health→custom op/attention numeric→single model→batch/KV churn→mode/profile/features→multi-device/P-D→fault/soak→performance/SLO。每级保存原始证据。

- `SOURCE_IMPLEMENTED`：fixed plugin包含Pyt/AoT、connector、ops与tests。
- `VENDOR_CLAIM × UNVALIDATED`：150 的 `WEB-QAIC-01/02/04` 给出 JIT/AoT 与设备健康工具的厂商资料。
- `UNKNOWN`：本轮未安装SDK/无device，所有DEVICE/PERF/PRODUCTION单元保持UNKNOWN。

## 故障收敛矩阵

| 故障 | 最小安全范围 | 必须隔离 |
|---|---|---|
| profile/QPC mismatch | request或startup | exec object/bindings |
| session timeout | session/worker | in-flight buffers/KV |
| SoC/MHI reset | device/replica | 全部 handles/QPC residency |
| communicator/P2P fault | rank group | collective epoch |
| QPC corruption | release tuple | artifact namespace |

支持单元必须分别标事实来源类型与验证成熟度，例如 `SOURCE_IMPLEMENTED × STATIC_REVIEWED`、`RELEASE_CONTRACT × PRODUCTION_QUALIFIED`，而非一个绿色布尔；完整字典见 02。`RECOMMENDATION`：`qaic-util` health、session/QPC manifest、plugin/vLLM SHA 和测试 artifacts 原子归档；当前终结论仍为 `UNKNOWN` 设备级。
