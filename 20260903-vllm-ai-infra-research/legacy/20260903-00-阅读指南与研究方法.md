# vLLM 与异构推理后端研究：阅读指南与方法

## 研究范围

本系列从 AI Infra 架构师视角解释 vLLM 的请求、调度、KV Cache、模型执行、编译、通信和服务接口，并分析 Ascend、Qualcomm Cloud AI、Tenstorrent、Google TPU 的接入方式及硬件约束。它不是安装手册，也不把“存在代码”写成“生产可用”。

## 证据标签

- `SOURCE_IMPLEMENTED`：固定 revision 中存在可达源码路径。
- `RELEASE_CONTRACT`：release、版本矩阵、镜像或 ModelSpec 明确承诺。
- `RUNTIME_VALIDATED`：在明确环境中真实运行通过。
- `PERFORMANCE_MEASURED`：具有设备、模型、精度、输入、输出、并发和版本的测量。
- `VENDOR_CLAIM`：厂商公开材料中的声明。
- `INFERENCE`：由源码和硬件特性推导，但尚未运行验证。
- `RECOMMENDATION`：架构选择建议。
- `UNKNOWN`：当前证据不足。

本次没有对应 Ascend、QAIC、TPU 或 Tenstorrent 硬件，因此 vendor 章节最高通常只能达到 `SOURCE_IMPLEMENTED` 或 `RELEASE_CONTRACT`。任何性能数字都不会自动升级为本地验证。

## 判断后端支持的证据阶梯

1. plugin entry point 能被发现；
2. Platform 能完成配置校验和 worker/runner 选择；
3. 模型、attention、KV layout、量化和通信路径存在；
4. 明确的 vLLM/plugin/runtime/driver/firmware/model tuple；
5. 真实硬件功能测试；
6. 数值评估、故障恢复和并发隔离；
7. 完整 workload 下的服务性能与稳定性。

只达到第 1 层不能称为“模型受支持”。

## 阅读顺序

先阅读 `01` 理解全栈约束，再读 `02`、`03`、`04` 建立 vLLM 控制面模型。随后阅读 `05` 的硬件比较框架和四份 vendor 文档。`10`、`11` 给出横向决策和新硬件接入方法，`12` 收录不能确认的问题。

## 研究限制

- 不下载模型权重、容器镜像或受限 SDK。
- 不在 vendor 硬件上执行，因此不作正确性或性能背书。
- main branch 会持续变化；本文结论绑定上述 revision。
- 厂商规格只用于解释架构，不用于无约束的性能排名。
- 软件兼容必须按完整 tuple 判断，不能只比较 package 名称。
