# 安全边界、Plugin 信任与租户隔离

## 文档契约

- **唯一问题**：部署vLLM与第三方plugin时，哪些输入/代码/缓存/设备边界需要信任或隔离。
- **In scope**：remote code、plugins、model artifacts、API、cache side channels、resource DoS、credentials。
- **Out of scope**：一般功能failure（84）、多租户调度性能（14）、具体CVE。
- **证据基线**：vLLM SECURITY/usage security/plugin loading与部署配置。

plugin entry point在进程中执行任意Python，通常与server同权限；安装即扩大trusted computing base。allowlist只控制加载，不验证供应链。应固定package/hash、最小权限、隔离build/runtime、审计依赖和禁止不可信自动发现。

模型/remote code/tokenizer/media decoder同样可执行或解析复杂输入。生产默认禁用不必要的trust_remote_code和endpoint plugins；artifact cache视为可执行内容，需完整性和权限。

租户隔离覆盖prompt/log、prefix/MM/compile caches、LoRA、metrics、GPU memory残留和timing。cache salt降低跨请求共享但不解决所有side channel；block复用若kernel越界会泄露前租户state。

DoS面包括超长prompt/output、grammar compile、媒体解码、logprobs、adapter churn、compile miss、connection慢读。所有入口在昂贵工作前做size/rate/auth limits，并把queue/memory有界。

credentials不进入CLI日志、trace或文档；容器device权限、network egress、filesystem按需开放。安全验收含threat model、SBOM/signature、malicious inputs、cache隔离、plugin冲突和资源耗尽；源码审计不能替代部署加固。

## Trust boundary 清单

| 资产 | 威胁 | 控制 |
|---|---|---|
| plugin/native op | 任意代码/供应链 | pin/hash/signature |
| model/tokenizer/media | remote code/parser | allowlist/sandbox/limit |
| KV/MM cache | 跨租户泄漏 | namespace/reuse tests |
| QPC/trace/artifact | 可执行替换 | manifest/只读/原子发布 |
| logs/metrics | prompt/secret | redaction/RBAC/retention |

以仓库 `SECURITY.md`、`docs/usage/security.md` 为起点。`RECOMMENDATION`：backend/模型纳入同一 TCB/SBOM；`UNKNOWN`：部署 IAM/network hardening。
