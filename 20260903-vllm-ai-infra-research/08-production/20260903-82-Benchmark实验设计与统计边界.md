# Benchmark 实验设计与统计边界

## 文档契约

- **唯一问题**：怎样设计可复现、可比较且不超越证据的推理benchmark。
- **In scope**：workload、warmup、open/closed loop、metrics、统计、hardware/software tuple。
- **Out of scope**：capacity决策（83）、硬件理论比较（90-95）、vendor结果。
- **证据基线**：vLLM benchmark工具、公开论文方法；不预填无设备数值。

先定义问题：单请求latency、最大throughput、SLO goodput、capacity还是成本。closed-loop会受客户端等待抑制arrival，适合交互；open-loop按外生速率到达，适合排队/SLO。二者数字不可直接比较。

workload需给prompt/output length联合分布、arrival process、model/quant、sampling、prefix/adapter/MM locality、并发、SLO。固定长度合成只回答窄microcase。

区分cold startup、compile/warmup、steady-state；warmup不能悄悄排除真实生产cache miss。报告p50/p90/p99和置信区间/重复次数，不只均值；throughput同时给request/s和token/s，goodput只计满足完整SLO的请求。

控制变量包括完整release tuple、power/clock、topology、background load、memory reserve和selected kernels。比较backend时要确认输出quality、功能配置和failure rate等价。OOM/reject不能从分母删除。

实验产物含命令/config、raw per-request records、环境probe、warmup日志和分析脚本。无硬件时只交付符号模型与实验协议，不伪造峰值。营销峰值、单kernel和E2E各有不同证据域。

## 实验矩阵与停止规则

先过 correctness/quality gate，再做 phase microbench，最后跑混合 open-loop。每个点重复到置信区间稳定，交替 backend 顺序降低热状态漂移。

| 结果 | 处理 |
|---|---|
| OOM/crash/reject | 计入错误率 |
| compile miss | 单列 cold 请求 |
| 未达质量阈值 | 性能比较无效 |
| thermal/power drift | run 标无效并保留 |
| p99 样本不足 | 不报伪精确值 |

`SOURCE_IMPLEMENTED`：vLLM benchmark harness 是采集入口；`RECOMMENDATION`：保存 raw records/tuple；`UNKNOWN`：本轮无 vendor 数值。
